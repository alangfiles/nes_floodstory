Priority 4: WRAM Collision Buffers

Implementation note for recovering normal RAM by moving persistent collision maps to PRG-RAM.

What was wrong

The three 240-byte collision maps occupied 720 bytes of the constrained $0300-$06FF normal-RAM area. The linker left only 20 bytes between ordinary data/BSS and the C stack, despite an existing 8 KiB WRAM region at $6000-$7FFF being reserved mostly by a filler array.

What changed

  • Added named collision-map size constants.
  • Moved c_map, c_map2, and c_metatile_map from BSS to the existing XRAM segment.
  • Reduced wram_array by exactly the 720 bytes assigned to the maps.
  • Preserved the existing symbols and call sites, so collision and stage code require no interface changes.

How to Test

  1. From this branch's worktree, run make and confirm labels.txt reports BSS size 0x1B and XRAM size 0x2000.
  2. Open floodstory.nes in Mesen and enter every available stage. Verify each room loads with the expected background and collision behavior.
  3. Exercise solid floors, walls, ladders, pits, and spikes on both sides of a room transition. Confirm the player neither passes through solid tiles nor collides with empty tiles.
  4. Cross a room boundary in each direction, then repeat the same collision checks. This confirms both collision maps are populated correctly from WRAM.
  5. In Mesen's memory viewer, inspect $6000-$7FFF after a room load to confirm collision map data changes there while normal RAM remains available for other state.

Validation

PASS: make completed and produced floodstory.nes.
